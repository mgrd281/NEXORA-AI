# Railway variables for JARVIS

Every environment variable each Railway service needs, for the step-by-step guide in
[docs/runbooks/deploy-railway.md](../../docs/runbooks/deploy-railway.md) (Arabic:
[deploy-railway.ar.md](../../docs/runbooks/deploy-railway.ar.md)). The source of truth is
[`apps/api/src/config.ts`](../../apps/api/src/config.ts); [`.env.example`](../../.env.example) has
the same names with comments.

Service names used below: **`Postgres`**, **`api`**, **`worker`**, **`web`** and (optional)
**`browser-worker`**. If you name them differently, the private domains change too
(`<service>.railway.internal`; check each service's Settings → Networking).

| Mark       | Meaning                                                                                                               |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| **req**    | the process refuses to start (or the feature cannot work) without it                                                  |
| **secret** | a credential: in Railway open the variable's ⋮ menu → _Seal_, never paste it into chats, screenshots or issues        |
| **build**  | also read while the image is **built** (Railway passes a service variable to a Dockerfile `ARG` of the same name)     |
| **ref**    | can be written as a Railway reference variable instead of a literal; **verify the syntax in Railway** before using it |

Railway reference syntax as we understand it (verify in Railway's _Variables_ docs and the
dashboard's autocomplete, which offers valid references when you type `${{`):
`${{api.RAILWAY_PRIVATE_DOMAIN}}` (another service's variable), `${{shared.NAME}}` (a shared
variable). Literal values always work and are what the examples below use.

## Generate the secrets

Run on your Mac (or any machine with OpenSSL); paste each value straight into Railway.

```bash
openssl rand -base64 32   # SECRET_ENCRYPTION_KEY: exactly 32 random bytes, base64 (44 characters)
openssl rand -hex 32      # METRICS_TOKEN (only if you scrape /metrics; at least 24 characters)
```

Equivalent with Node.js: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.
The two database passwords are generated by `scripts/railway/bootstrap-db.sh`, which prints the
complete `DATABASE_URL` and `DATABASE_OWNER_URL`. The owner **account** password (the one you sign
in with) is never a variable: you type it once into `create-owner` (see the guide).

**Keep a copy of `SECRET_ENCRYPTION_KEY` in your password manager.** It encrypts stored connection
secrets (SMTP passwords, OAuth tokens); a database backup is useless for those without it, and
changing it means reconnecting them ([operations runbook](../../docs/runbooks/operations.md#rotate-secret_encryption_key)).

## Minimal working setup

Postgres + `api` + `worker` + `web`, no file storage (`STORAGE_DRIVER=none`), no browser worker,
the offline planner (no `ANTHROPIC_API_KEY`). Enough to sign in on the web and the iPhone, connect
web access and SMTP email, and run "summarize this page and email it to me".

### `Postgres` (Railway's PostgreSQL template)

Nothing to set. It provides `DATABASE_URL` / `DATABASE_PUBLIC_URL` for its **superuser**; only
`bootstrap-db.sh` uses them. **Never** give the superuser URL to `api`, `worker` or
`browser-worker`: it would bypass Row-Level Security (tenant isolation).

### `api` (config file `/deploy/railway/api.json`)

| Variable                   | Req | Secret | Example                                                                 | Notes                                                                                                                                                                      |
| -------------------------- | --- | ------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                 | req |        | `production`                                                            | The image already sets it; set it anyway so nothing can run in development mode                                                                                            |
| `PORT`                     | req |        | `4000`                                                                  | Fixed so the web's `API_ORIGIN`, the healthcheck and the domain's target port agree                                                                                        |
| `HOST`                     | req |        | `::`                                                                    | All IPv6 **and** IPv4 addresses, so Railway's private network reaches the API. If the deploy log shows `listen EAFNOSUPPORT ... :::4000`, use `0.0.0.0`                    |
| `DATABASE_URL`             | req | secret | `postgresql://jarvis_app:<pw>@postgres.railway.internal:5432/railway`   | Runtime role `jarvis_app` (RLS enforced), printed by `bootstrap-db.sh`                                                                                                     |
| `DATABASE_OWNER_URL`       | req | secret | `postgresql://jarvis_owner:<pw>@postgres.railway.internal:5432/railway` | Used only by the pre-deploy command `node dist/migrate.js`. Railway gives the pre-deploy step the service's variables, so it lives here; the server process never reads it |
| `WEB_ORIGIN`               | req |        | `https://web-production-xxxx.up.railway.app`                            | The web app's address **exactly** as in the browser's address bar: `https://`, no path, no trailing `/`. ref: `https://${{web.RAILWAY_PUBLIC_DOMAIN}}`                     |
| `SECRET_ENCRYPTION_KEY`    | req | secret | output of `openssl rand -base64 32`                                     | **Same value in `worker`**                                                                                                                                                 |
| `SECRET_ENCRYPTION_KEY_ID` |     |        | `k1`                                                                    | Default `k1`; same value in `worker`                                                                                                                                       |
| `STORAGE_DRIVER`           |     |        | `none`                                                                  | Default `none` in production: uploads are unavailable and the UI says so                                                                                                   |
| `LOG_LEVEL`                |     |        | `info`                                                                  | `fatal` `error` `warn` `info` `debug` `trace` `silent`                                                                                                                     |
| `SESSION_TTL_DAYS`         |     |        | `30`                                                                    | 1–90                                                                                                                                                                       |
| `APPROVAL_TTL_HOURS`       |     |        | `24`                                                                    | 1–168; same value in `worker`                                                                                                                                              |
| `APP_VERSION`              |     | build  | a git SHA                                                               | Shown in the assistant status. ref (verify): `${{RAILWAY_GIT_COMMIT_SHA}}`                                                                                                 |

### `worker` (config file `/deploy/railway/worker.json`)

Same image as `api`, started with `node dist/worker.js`. It serves no HTTP and has no healthcheck.

| Variable                   | Req | Secret | Example / value   | Notes                                                                                            |
| -------------------------- | --- | ------ | ----------------- | ------------------------------------------------------------------------------------------------ |
| `NODE_ENV`                 | req |        | `production`      |                                                                                                  |
| `DATABASE_URL`             | req | secret | same as `api`     | `jarvis_app`                                                                                     |
| `WEB_ORIGIN`               | req |        | same as `api`     | The worker refuses to start in production without an `https` one. ref: `${{api.WEB_ORIGIN}}`     |
| `SECRET_ENCRYPTION_KEY`    | req | secret | **same as `api`** | The API seals connection secrets, the worker opens them; different keys = every email send fails |
| `SECRET_ENCRYPTION_KEY_ID` |     |        | same as `api`     |                                                                                                  |
| `STORAGE_DRIVER`           |     |        | same as `api`     |                                                                                                  |
| `WORKER_CONCURRENCY`       |     |        | `2`               | Jobs in parallel (default 4, 1–32). 2 is plenty for one person and keeps memory low              |
| `APPROVAL_TTL_HOURS`       |     |        | same as `api`     |                                                                                                  |
| `LOG_LEVEL`, `APP_VERSION` |     |        | as for `api`      |                                                                                                  |

Not needed here: `PORT`, `HOST`, `DATABASE_OWNER_URL` (do not add the owner URL to the worker).

### `web` (config file `/deploy/railway/web.json`)

| Variable     | Req | Secret | Example                            | Notes                                                                                                                                                                                                                                                                                                                                       |
| ------------ | --- | ------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `API_ORIGIN` | req | build  | `http://api.railway.internal:4000` | Where the same-origin `/api` proxy forwards, over Railway's private network (`http`, the `api` service's private domain and `PORT`). **Read at build time** (Next.js rewrites) and at run time: after changing it, rebuild (redeploy from the latest commit), not only restart. ref: `http://${{api.RAILWAY_PRIVATE_DOMAIN}}:${{api.PORT}}` |
| `PORT`       | req |        | `3000`                             | The web domain's target port                                                                                                                                                                                                                                                                                                                |
| `HOSTNAME`   |     |        | `0.0.0.0`                          | The image already sets it; Next.js' standalone server binds to it. If the domain answers "Application failed to respond", try `::`                                                                                                                                                                                                          |
| `NODE_ENV`   |     |        | `production`                       | Image default                                                                                                                                                                                                                                                                                                                               |

The web service holds **no secrets**.

### Real AI planning (Anthropic)

| Variable                                       | Services         | Secret | Notes                                                                                                                                                                                           |
| ---------------------------------------------- | ---------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`                            | `api` + `worker` | secret | The worker plans with it; the API reports the planner mode the UI shows. Both, or the UI says "offline"                                                                                         |
| `OPENAI_API_KEY`                               | `api`            | secret | Optional natural voice (`POST /v1/voice/speech`, gpt-4o-mini-tts). Without it the apps use the device voice. `OPENAI_TTS_VOICE` (default `coral`) and `OPENAI_TTS_MODEL` change the voice/model |
| `MODEL_FAST` / `MODEL_BALANCED` / `MODEL_DEEP` | `api` + `worker` |        | Repository defaults `claude-haiku-5-5` / `claude-sonnet-5-5` / `claude-opus-5-5`; change only on purpose                                                                                        |

Set a spending limit in the Anthropic console; see [docs/costs.md](../../docs/costs.md).

### File storage (attachments, browser evidence): S3-compatible

Same values on `api`, `worker` and (if you run it) `browser-worker`.

| Variable                                      | Req with s3 | Secret | AWS S3 example | Cloudflare R2 example                                                                                                          |
| --------------------------------------------- | ----------- | ------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `STORAGE_DRIVER`                              | req         |        | `s3`           | `s3`                                                                                                                           |
| `S3_BUCKET`                                   | req         |        | `jarvis-files` | `jarvis-files`                                                                                                                 |
| `S3_REGION`                                   |             |        | `eu-central-1` | `auto`                                                                                                                         |
| `S3_ENDPOINT`                                 |             |        | (unset)        | `https://<account id>.eu.r2.cloudflarestorage.com` (EU jurisdiction bucket) or `https://<account id>.r2.cloudflarestorage.com` |
| `S3_FORCE_PATH_STYLE`                         |             |        | `false`        | `true`                                                                                                                         |
| `S3_PREFIX`                                   |             |        | `jarvis/`      | `jarvis/`                                                                                                                      |
| `S3_SSE` / `S3_SSE_KMS_KEY_ID`                |             |        | `AES256`       | `AES256`                                                                                                                       |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | req         | secret | IAM user keys  | R2 API token's access key id / secret                                                                                          |

- The bucket must be **private** (block all public access). The credentials need read, write and
  delete on objects under the prefix and `HeadBucket` (S3: `s3:GetObject`, `s3:PutObject`,
  `s3:DeleteObject`, `s3:ListBucket` on that bucket only).
- JARVIS sends `x-amz-server-side-encryption: AES256` and a SHA-256 checksum with **every** upload
  ([`storage/s3.ts`](../../apps/api/src/modules/storage/s3.ts)). AWS S3 supports both. **Not
  verified against R2 or other S3-compatible services**; if uploads fail with `NotImplemented` or
  `InvalidArgument` in the API logs, the service rejects one of these headers — use AWS S3.

### Browser worker (optional; read the guide's "Browser worker" section first)

Config file `/deploy/railway/browser-worker.json` (image `apps/api/Dockerfile.browser`).

| Variable                                         | Req | Secret | Value                       | Notes                                                                                        |
| ------------------------------------------------ | --- | ------ | --------------------------- | -------------------------------------------------------------------------------------------- |
| `NODE_ENV`                                       | req |        | `production`                |                                                                                              |
| `DATABASE_URL`                                   | req | secret | same as `api`               | `jarvis_app` — its only credential                                                           |
| `BROWSER_EXECUTABLE_PATH`                        | req |        | `/opt/pw-browsers/chromium` | The image sets it; required in production                                                    |
| `STORAGE_DRIVER` + `S3_*` + `AWS_*`              | req |        | same as `api`               | Without storage every browser job fails and the API never offers the browser                 |
| `BROWSER_WORKER_CONCURRENCY`                     |     |        | `1`                         | Default 2; each Chromium session needs several hundred MB                                    |
| `BROWSER_SITES`                                  |     |        | (unset)                     | Comma-separated recipe ids; default all available (in production today: none, see the guide) |
| `LOG_LEVEL`, `SENTRY_*`, `OTEL_*`, `APP_VERSION` |     |        | as for `api`                |                                                                                              |

**It must not have** — the process refuses to start with any of them set:
`SECRET_ENCRYPTION_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_CLIENT_SECRET`, `MICROSOFT_CLIENT_SECRET`,
`DATABASE_OWNER_URL`, `METRICS_TOKEN`, `TWILIO_AUTH_TOKEN`. Do not share project-wide (shared)
variables with this service.

### Google and Microsoft accounts (OAuth)

On `api` **and** `worker` (the API runs the sign-in, the worker refreshes tokens and sends).

| Variable                                          | Secret              | Notes                                                                                                                                     |
| ------------------------------------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`       | secret (the secret) | Both or neither. Google Cloud Console → APIs & Services → Credentials → OAuth client ID, type **Web application**                         |
| `MICROSOFT_CLIENT_ID` / `MICROSOFT_CLIENT_SECRET` | secret (the secret) | Both or neither. Microsoft Entra admin center → App registrations → Certificates & secrets                                                |
| `MICROSOFT_TENANT`                                |                     | `common` (default), `organizations`, `consumers`, or a tenant id / domain                                                                 |
| `OAUTH_REDIRECT_URIS`                             |                     | Optional. Default `<WEB_ORIGIN>/connections/callback`. If you set it, use the same value on `api` and `worker`; https only, exact strings |

Register exactly this **redirect URI** with each provider (it is also the one the iPhone app uses):

```
https://<your web domain>/connections/callback
e.g. https://web-production-xxxx.up.railway.app/connections/callback
```

- Google: OAuth client → _Authorized redirect URIs_. While the consent screen is in **Testing**,
  add your Google account as a test user (unverified-app warning is expected).
- Microsoft: App registration → Authentication → platform **Web** → _Redirect URIs_.
- When you move to a custom domain, add the new URI at the providers **before** changing
  `WEB_ORIGIN`.

### Phone calls (Twilio)

On `api` (verifies the signed webhooks) **and** `worker` (places the calls). Needs the `api`
service's **public** domain.

| Variable                    | Req         | Secret | Example                                      | Notes                                                                                                                                        |
| --------------------------- | ----------- | ------ | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `TWILIO_ACCOUNT_SID`        | all three   |        | `AC` + 32 hex                                | All three or none                                                                                                                            |
| `TWILIO_AUTH_TOKEN`         | all three   | secret |                                              | Never on `browser-worker`                                                                                                                    |
| `TWILIO_FROM_NUMBER`        | all three   |        | `+4930123456789`                             | A voice-capable number of the account, E.164                                                                                                 |
| `PUBLIC_WEBHOOK_BASE_URL`   | with Twilio |        | `https://api-production-xxxx.up.railway.app` | The API's public origin (no path, no trailing `/`); webhook signatures are checked against it. ref: `https://${{api.RAILWAY_PUBLIC_DOMAIN}}` |
| `CALL_ALLOWED_HOURS`        |             |        | `08:00-20:00`                                | Callee's local time                                                                                                                          |
| `CALL_MAX_SECONDS`          |             |        | `300`                                        |                                                                                                                                              |
| `CALL_MAX_PER_DAY`          |             |        | `10`                                         |                                                                                                                                              |
| `CALL_PRICE_PER_MINUTE_USD` |             |        | `0.05`                                       | Shown as the cost estimate in approvals                                                                                                      |
| `CALL_ALLOWED_COUNTRIES`    |             |        | `DE,AT,CH`                                   | Default: the country of `TWILIO_FROM_NUMBER`                                                                                                 |

JARVIS passes the webhook URLs with each call it creates, so nothing has to be configured on the
number in the Twilio console. Allow the destination countries under Twilio's voice geographic
permissions. Read [docs/security/telephony.md](../../docs/security/telephony.md) before calling
real people.

## Never set these on Railway

Development and test switches. In production (`NODE_ENV=production`) the API, worker and browser
worker **refuse to start** with them (checked: each one below exits with an error):
`FETCH_ALLOW_PRIVATE_HOSTS`, `SMTP_ALLOW_INSECURE_LOCALHOST=true`, `WEBHOOK_ALLOW_INSECURE_HOSTS`,
`STORAGE_DRIVER=local`, `GOOGLE_BASE_URL_OVERRIDE`, `MICROSOFT_BASE_URL_OVERRIDE`,
`TWILIO_BASE_URL_OVERRIDE`, `BROWSER_ALLOW_PRIVATE_HOSTS`, `BROWSER_FIXTURE_ORIGIN`, an `http://`
`WEB_ORIGIN`, `OAUTH_REDIRECT_URIS` or `PUBLIC_WEBHOOK_BASE_URL`. Also never set
`NODE_ENV=development`, which would switch those protections off.

## Copy-paste blocks (Railway → service → Variables → Raw Editor)

Replace every `<…>`. Then seal the secret ones.

`api`:

```
NODE_ENV=production
PORT=4000
HOST=::
DATABASE_URL=<DATABASE_URL printed by bootstrap-db.sh>
DATABASE_OWNER_URL=<DATABASE_OWNER_URL printed by bootstrap-db.sh>

```

```
NODE_ENV=production
DATABASE_URL=<same as api>
WEB_ORIGIN=https://<web domain>
SECRET_ENCRYPTION_KEY=<same as api>
```
